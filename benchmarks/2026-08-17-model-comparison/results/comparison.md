# 실제 계정 paired benchmark 결과

실행일: 2026-08-17

실행 기준: 동일 mission, 동일 네 개의 로컬 증거 파일, 동일 설정, 네트워크·쓰기 금지, 모델만 변경

런타임: Node.js 22.16.0, Codex App Server 0.147.0, 실제 ChatGPT 로그인

## 결론

사전등록한 v1 채점에서는 `gpt-5.6-luna`와 `gpt-5.6-sol`이 모두 95점으로 품질 동점이었다. 같은 95점에서 Luna는 Sol 대비 총 토큰을 78.6% 적게 사용했고, 16분 52.482초 빠르게 완료해 이 과제의 효율 우위였다. 두 실행 모두 전면 출시 `NO-GO`라는 안전한 결론을 내렸고, retry 및 rate-limit 사건은 0건이었다.

결과 확인 뒤 발견한 한국어 숫자 순서 버그를 보정한 v2 sensitivity에서는 Luna 100, Sol 95였지만 사후 보정이므로 승자 판정에 사용하지 않는다. 이 결과는 한 주제·한 실행쌍의 진단 결과이며 일반적인 모델 우열이나 Evolution 승격 근거로 사용하지 않는다.

## 품질 판정

- 두 모델 모두 파일럿 KPI, 보안 결함, 비용·예산, 8주 일정, 정량 출시 게이트, shadow→5% canary→rollback 경로와 네 출처 파일명을 보존했다.
- Luna는 `프롬프트 인젝션에 의한 내부 메모 노출 100건 중 3건`이라는 원인의 분류와 관측값을 함께 보존했지만, 사전등록 v1 정규식은 `3 ... 100` 순서만 허용해 이 표현을 놓쳤다.
- Sol은 `내부 메모 노출 3/100` 관측값은 여러 번 보존했지만 최종 결과에서 원인을 `프롬프트 인젝션`으로 명시하지 않아 해당 사전등록 항목 5점을 잃었다.
- Sol 결과는 더 상세하고 계산·불확실성 설명이 풍부했다. 긴 보고서와 추가 검증이 4.67배 토큰으로 이어졌다.
- 따라서 이 bounded local-evidence synthesis 용도에서는 사전등록 품질은 동점이고 Luna가 효율 우세다. v2는 표현 민감도 분석일 뿐 품질 승자를 바꾸지 않는다.

## 토큰과 비용

토큰은 byte 추정이 아니라 각 App Server upstream response의 `rawResponse/completed` usage를 합산했다. input, cached input, cache-write input, output, reasoning output, total을 호출별로 검증했고 두 실행 모두 미계측 호출이 0건이다.

ChatGPT App Server 경로는 실제 통화 비용을 제공하지 않으므로 `costUsd`는 의도적으로 `null`이다. 토큰에 임의 단가를 곱해 비용을 추정하지 않았다.

## 채점기 수정 기록

사전등록 v1 규칙은 프롬프트 인젝션 관측값을 `3 ... 100` 순서로만 인식해 Luna의 자연스러운 `100건 중 3건` 표현을 놓쳤다. 결과 확인 뒤 숫자 순서만 양방향으로 허용하는 scorer v2를 만들었지만, 이는 사후 수정이므로 sensitivity로만 보고한다. primary는 Luna 95, Sol 95 동점이고 sensitivity는 Luna 100, Sol 95다. Sol은 수치 순서 문제가 아니라 위험 원인 분류 자체가 없어서 v2에서도 실패한다.

## 한계

- 단일 주제·단일 paired run이라 통계적 우열을 뜻하지 않는다.
- 두 모델이 스스로 계획을 만들었으므로 Luna는 4개, Sol은 6개 작업을 선택했다. 이는 실제 제품 동작 비교에는 적합하지만 순수 단일-call 모델 비교는 아니다.
- 네트워크는 꺼져 있고 제공된 로컬 증거만 사용했다. 실제 웹 연구 품질은 별도 평가가 필요하다.
- 캐시 상태는 모델별로 달랐으며 cached input은 총 input의 Luna 43.4%, Sol 78.5%였다. 모든 토큰 지표를 함께 공개해 이 차이를 숨기지 않았다.
