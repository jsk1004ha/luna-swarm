현재 저장소의 README.md와 docs 안의 공개 설명만 근거로 Luna Swarm GitHub 소개 문서에 대한 읽기 전용 편집 감사 보고서를 작성하라.

실제 구현과 저장소에 남은 검증 증거만 사용하고 과장하거나 미검증 주장을 만들지 마라. GitHub 방문자가 다음을 빠르게 이해하도록 정보 구조와 표현을 평가하라.

1. 첫 화면 가치 제안과 신뢰 가능한 상태 요약
2. 단순 병렬 에이전트 방식과 구분되는 실행 구조
3. 시작 안내, 실제 실행 흐름, UI, 진단과 운영 안내의 탐색성
4. Host Tool Broker, Work Order, 독립 검증, Single Committer, evaluator, Shadow/Canary의 권위 경계
5. 실제 Luna/Sol benchmark 결과와 해석 한계
6. 저장공간 유지관리와 보고서 UI
7. 문서 링크, 알려진 한계, 기여 및 검증 안내

배지, 표, 접기 섹션, Mermaid 다이어그램, 이모지는 정보 밀도와 가독성을 높일 때만 절제해 제안하라. 외부 이미지와 네트워크 자료는 배제한다. 링크와 수치는 저장소에서 확인하고, 상충하거나 확인되지 않는 내용은 한계로 표시하라. 최종 산출물에는 권장 섹션 순서, 바로 인용할 수 있는 문구 블록, 유지할 기존 근거 링크, 삭제하거나 축약할 중복을 포함하라.
