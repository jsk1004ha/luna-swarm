로컬 evidence/ 디렉터리에 제공된 네 개의 문서만 근거로 Luna Swarm의 출시 준비 보안·운영 감사를 분석하고 한국어 경영진 보고서로 답하라.

필수 조건:
- 네 문서를 실제 read/search 도구로 확인하고 정확한 파일명을 근거로 표시한다.
- 기본 일반 Swarm 동작, read/search Host Tool Broker, opt-in CodingPipeline, Evolution 평가·승격·rollback, crash/resume와 storage 보존 경계를 구분한다.
- 구현된 보장, 기본값, 명시적 opt-in, 문서상 미래 기능, 문서 간 불일치, 아직 검증되지 않은 항목을 섞지 않고 분리한다.
- 각 Critical/High 위험에는 영향, 가능한 실패 경로, 완화책, 재확인 방법을 제시한다.
- 전체 제품 출시 가능, 조건부 출시, 보류 중 하나를 명확히 결정하고 30/60/90일 우선순위를 제시한다.
- 외부 자료나 존재하지 않는 코드·검증 사실을 만들지 않는다.
- 파일을 수정하지 않고 네트워크 없이 읽기 전용으로 답한다.

최종 보고서는 경영진이 구현 보장과 문서 주장, 남은 출시 차단 조건을 바로 구분할 수 있을 정도로 구체적이어야 한다.
