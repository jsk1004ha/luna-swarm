# 참고 수직 조직

사용자가 제공한 형태를 Luna Swarm의 동적 팀 모델로 옮긴 예시입니다. 실제 실행은 목표 난이도에 따라 일부 직급을 건너뛰거나 더 많은 병렬 가지를 만듭니다.

```mermaid
flowchart TD
  C["회장 · 사용자"] --> VC["부회장 · 프로젝트 총괄"]
  VC --> P1["사장 · 사업군 A"]
  VC --> P2["사장 · 사업군 B"]
  P1 --> E1["전무 · 프로그램 A"]
  P2 --> E2["전무 · 프로그램 B"]
  E1 --> D1["이사 · 기능 A"]
  E2 --> D2["이사 · 기능 B"]
  D1 --> G1["부장 · 팀 A1"]
  D1 --> G2["부장 · 팀 A2"]
  D2 --> G3["부장 · 팀 B1"]
  D2 --> G4["부장 · 팀 B2"]
  G1 --> DM1["차장"]
  G4 --> DM2["차장"]
  DM1 --> S1["과장 · 섹션 A"]
  DM2 --> S2["과장 · 섹션 B"]
  S1 --> A1["대리"]
  S2 --> A2["대리"]
  A1 --> W1["사원/인턴 · 실무"]
  A2 --> W2["사원/인턴 · 실무"]
```

효율 규칙 때문에 “직접 작업 없이 하위 노드 하나만 전달하는 관리자”는 생성할 수 없습니다. 깊은 계층을 쓰려면 각 단계가 직접 작업을 소유하거나 두 개 이상의 하위 보고를 실제로 종합해야 합니다.
